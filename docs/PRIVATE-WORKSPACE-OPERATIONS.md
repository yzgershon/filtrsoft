# Private workspace operations

Introduced September 12, 2026. This file describes implemented behavior; HANDOFF.md records deployment status.

## Access

New password and configured social account creation is open by default, as Yish requested September 13. An explicitly set `FILTRSOFT_REGISTRATION=closed` closes new registration; existing accounts can still sign in. Account-owned notes, purchases, dismissals, pins and follow-ups remain isolated. This is not an account allowlist.

The frontend reads `providers.registrationOpen` from `/v1/auth/me`. Private mode serves a sign-in entry instead of public signup copy. Anonymous health checks retain readiness, engine, coverage counts and scoring state for deployment monitoring. Signed-in health requests retain pipeline diagnostics. Thumbnail requests require the same account session as listing data and use private browser caching.

## Evidence and personal records

- `GET /v1/checks/:id/price-history`: actual asking-price observations, newest observation time first with ID as tie-breaker. Pages contain 50 rows and a listing-specific `before` cursor. No baseline or sale is fabricated at read time.
- `GET/PUT /v1/checks/:id/inspection`: account-owned notes and manual observations. Saves require the current revision and evidence basis. Changed questions or listing identity invalidate old check answers; historical revisions remain. Manual checks never alter canonical verdicts.
- `GET /v1/purchases`: account-owned purchase records, latest 200, with explicitly scoped inventory and completed-sale summaries.
- `PUT /v1/purchases/:id`: correction or completion of a purchase/sale record. Requires its revision. Every edit appends before/after snapshots. Original decision snapshots stay unchanged.

Money is integer cents. Blank amounts are unknown. Recorded profit requires known purchase price, sale price, fees, shipping and other costs. Old rows retain NULL other costs until explicitly recorded. Profit is before tax and includes labor only if entered in other costs. Disappearance of a listing is not a sale. Sold dates are reported dates; the UI does not infer actual purchase dates or time to sell from when a purchase was recorded.

Inspection and sale drafts remain in the current browser tab's session storage when their forms close. They are not cross-device sync. A mismatched record revision is shown for recovery instead of silently applying stale values. Successful saves use the server's revision fence; a timeout after the server committed can require reloading to see the result.

## Database and performance

`installWorkspace` adds outcome cost/revision columns and inspection/revision tables. It is additive and runs after the learning schema. Do not drop these tables to roll back frontend code. Backups must include them; the existing full-database SQLite backup workflow does.

Facts and asking-price observations commit in one transaction. Invalid observation timestamps are rejected and new accepted timestamps are normalized to ISO. Archive health caches verified metadata by path and file identity/timestamps, while import acknowledgement is read freshly. Archive import still validates the whole file. The shipped comp archive was not regenerated by this pass.

Stored listing reads and writes have separate bounded rate buckets from source checks and authentication. Normal tab navigation no longer consumes the remote source-check quota. Frontend JSON requests have a 15-second deadline covering response bodies as well as initial response headers.

## Verification commands

Use the existing Bun binary where it is not on PATH. Never install a second copy just for a test.

```powershell
bun test
node C:/Dev/filtrsoft/node_modules/typescript/bin/tsc --noEmit
node web/node_modules/vite/bin/vite.js build web
node src/browser/workspace-check.mjs
node src/browser/detail-check.mjs
node src/browser/comparison-check.mjs
docker build --platform linux/arm64 --target verification --tag filtrsoft-workspace-verification .
docker run --rm --network none filtrsoft-workspace-verification
```

The workspace browser harness runs the compiled frontend and real API on loopback with a disposable database, generated thumbnail and synthetic accounts. External fetches are disabled. Node drives Chrome; Bun serves SQLite/API. It cleans up only its own process and generated temporary directory. Ports 3210, 3198 and 3205 must be available for the respective harnesses. Do not kill an unrelated process to claim them.

Production verification is separate: confirm the deployed commit and bundled asset hashes, private registration state, health and anonymous data gates. Do not count fixture saves as verification on a real phone or a real production account.

## Operational limits that code does not erase

Laptop sources still require the laptop agent and manually established browser sessions. Sold evidence ages out after 90 days. A healthy deployed API does not imply fresh laptop collection. The new More > Pipeline status screen makes this visible; it does not launch a crawl. Free verified native gaming FPS coverage remains unavailable, and reference rendering scores remain explicitly separate.
